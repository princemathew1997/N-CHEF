# N-CHEF | Executive Chef guide

Revision: 22 October 2026 | N-CHEF 2.3.0

Existing Supervisor accounts now use the Executive Chef role with their existing credentials and assigned outlets. Purchaser (Supervisor) is a separate role managed by Admin.

## Navigation and assignments

Sign-in opens Manage Request. Select the N-CHEF logo to return to your role's home page. Your smaller role menu uses direct links. A single assigned outlet is fixed; accounts assigned several outlets can choose among permitted outlets. Other outlets are not available for review.

Use Stock Overview and Stock History to inspect permitted stock. Cuisine Deliveries shows issued goods and reported problems. Executive Chef does not approve purchasing, receive or distribute stock, maintain setup records or create accounts.

## Review requests together

Open Manage Request to inspect cuisine requests. Existing section acceptance controls accept that section's requests for consolidation; they do not confirm physical delivery or issue stock.

Use the review controls to inspect items and edit quantities before selecting Approve all reviewed items. This accepts the items in that review so they are ready to consolidate; it does not replace the Purchaser/Admin approval step. Review the full list before confirming.

Reject replaces deletion for a rejected cuisine request. Provide a reason; the request remains recorded and its owner receives the rejection information. For a rejected request, use Review / edit / approve to revise quantities and approve it again. A rejected consolidated request is reviewed with its linked items together before consolidation and resubmission.

## Save edits and consolidate

1. Open Consolidate Request for the assigned outlet and review the accepted cuisine quantities.
2. Change quantities as required. Every changed cuisine quantity needs an explanatory note, even if changes offset each other and the item total stays the same. Blank notes are highlighted before submission.
3. Use Save edits to preserve draft quantities and notes without advancing the workflow. Reopening or reloading restores saved edits.
4. Review the summary and submit to Purchaser/Admin. Approval, purchasing and stock issue happen separately.

Only one pending consolidation is allowed per outlet. If more cuisine requests arrive while it awaits approval, recall your unapproved consolidation, combine the requests and submit again. Recall keeps the original request records and an audit of the prior consolidation. An approved order or one with downstream purchasing cannot be recalled.

Executive Chef Raise Request supports today and the preceding three IST days. Backdating requires a meaningful justification; Cuisine Heads use today only. Existing items for the chosen date/outlet must be edited through the initial order rather than selected again as duplicate items.

## Follow deliveries and stock movements

Cuisine Deliveries groups items by dispatch to each cuisine. Expand a card for issued/received quantities, reasons, View request and Stock movement links where available. Needs attention includes older unfinished dispatches; Today shows today's dispatches; History contains fully handled dispatches.

Use Filters and page controls instead of searching one long log. Filter by permitted outlet, cuisine, status, item, order reference and IST dates. In Stock History, filter by item, vendor, movement type, person and dates; it starts with today. Different units remain separate on item rows.

## Notifications and conflicts

Requests, rejection reasons and delivery issues appear in Notifications and relevant badges. Coordinate delivery discrepancies with Purchaser or Admin, who records the resolution. Mark notifications read after review. Shared changes refresh while the app is visible; unsaved form text is preserved where supported. A concurrent save can be rejected to avoid overwriting another user's changes: refresh, inspect and retry.
